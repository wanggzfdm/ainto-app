# uTools 风格主界面改造设计

日期：2026-09-04

## 目标

将 Ainto 主搜索页从纵向结果列表改为参考截图中的 uTools 风格应用宫格，使常用应用和功能入口可以通过大图标快速识别和启动。

参考图：`/Users/wanggzh/Downloads/Snapzy/Snapzy_2026-09-04_16-39-57_371.png`

本次只改造 `MainView` 的主搜索页，不改变搜索、排序、打开结果和 Action 的业务逻辑。

## 页面结构

主搜索页从上到下包含以下区域：

1. 顶部一体化搜索输入区。
2. 分区标题行：左侧显示“最近使用”，右侧显示“展开（数量）”。
3. 应用结果宫格。

删除当前主搜索页底部的状态文字、分隔线和全部快捷键提示。

### 搜索输入区

- 普通应用搜索模式继续显示搜索图标。
- 输入框提示文案调整为“搜索应用和指令/粘贴文件或图片”。
- Claude 模式继续使用现有 Claude 图标和提示文案。
- 保留 `Tab` 切换 AI 模式的现有能力；其提示应融入搜索区域，不增加独立底栏。
- 查询变化仍调用现有 `performSearch(query:)`。
- Enter 仍打开当前选中结果。

### 分区标题行

- 仅在应用模式且存在结果时显示。
- 左侧文案固定为“最近使用”。
- 右侧显示“展开（N）”，其中 `N` 为当前结果数量。
- 第一版中“展开”只承担视觉提示，不新增折叠、分页或模式切换行为，避免引入没有明确需求的新功能。

### 应用宫格

- 使用 SwiftUI `LazyVGrid` 呈现结果。
- 每项由较大的应用图标和下方单行名称组成。
- 不再显示当前列表中的 `subtitle`。
- 名称超长时单行截断，不能挤压相邻宫格项。
- 宫格按行优先顺序映射 `viewModel.results`，保持原有搜索排序。
- 宫格宽度、列数、图标尺寸、间距和内边距应依据参考截图与现有 680pt 面板宽度协调，优先接近参考图的横向高密度布局。
- 结果过多时使用纵向滚动；选中项变化时自动滚动到可见区域。

## 交互

### 鼠标

- 单击宫格项：更新 `selectedIndex`。
- 双击宫格项：更新选中项并调用现有 `openSelected()`。
- 右键宫格项：继续展示该结果已有的 Action context menu。

### 键盘

- 左方向键：移动到前一个结果。
- 右方向键：移动到后一个结果。
- 上方向键：移动到上一行同列或最接近的位置。
- 下方向键：移动到下一行同列或最接近的位置。
- 宫格边界处不越界；最后一行不足一整行时，垂直移动应落到该行最后一个有效项。
- Enter：打开当前选中结果。
- Escape、`Cmd+K`、`Tab` 和已有编辑快捷键继续遵循现有行为。

为了让二维导航可测试，索引计算应提取为无 UI 依赖的纯逻辑，例如输入当前索引、结果数量、列数和方向，返回目标索引。

## 选中态

- 选中态作用于完整宫格单元，而不只是文字。
- 使用低透明度强调色背景或描边、连续圆角和适度内边距，视觉上接近参考图。
- 选中态必须在深色和浅色系统外观下保持可辨识。
- 未选中项保持透明，避免形成传统列表或厚重卡片墙。

## 空状态与模式边界

- 结果为空时不显示“最近使用”和“展开（0）”，页面只保留搜索输入区。
- Claude 模式不显示应用宫格和分区标题，维持当前行为。
- JSON Formatter、Snippets、AI Commands、Claude 等子页面不在本次改造范围内。
- 搜索结果的数据模型、排序规则、刷新逻辑、打开行为和 Action 定义不变。

## 窗口与视觉

- 保留当前 `VisualEffectBackground`、玻璃材质、16pt 外圆角、边框和阴影。
- 主面板继续以约 680pt 宽度为基准，不在本次需求中重构 `SearchPanel` 的窗口管理。
- 页面高度继续随内容变化，但结果区设置合理的最大高度，超过后滚动。
- 不保留现有底部 footer，因此无结果时窗口高度会比当前实现更紧凑。

## 组件边界

建议将现有 `ResultRow` 替换为职责单一的宫格单元组件，例如 `ResultGridItem`：

- 输入：`SearchResult` 和 `isSelected`。
- 负责：图标、标题、选中态和可点击内容区域的视觉呈现。
- 不负责：修改 `SearchViewModel`、打开应用或构造 Action。

二维导航逻辑放在独立纯函数或轻量类型中，以便通过 Swift 单元测试验证。

## 测试策略

生产逻辑变化必须先写失败测试，再实现。

单元测试至少覆盖：

1. 左右移动不会越过结果数组边界。
2. 上下移动按列数跨行。
3. 从完整行移动到不足列数的最后一行时落到最后一个有效项。
4. 空结果和单个结果不会产生非法索引。
5. 列数为非正数时采用安全行为，不崩溃。

另外运行现有 Swift 测试和构建，确认其他页面仍可编译。

SwiftUI 视觉和鼠标交互若现有项目没有 UI 测试基础设施，则通过编译验证和人工启动检查完成，不为本次改造额外引入 UI 测试框架。

## 验收标准

- 主搜索结果不再以纵向列表行呈现。
- 页面结构和视觉层级接近提供的 uTools 截图。
- 结果以大图标加单行名称的多列宫格呈现，不显示副标题。
- 页面显示“最近使用”和“展开（结果数量）”。
- 当前底部状态栏和快捷键提示完全移除。
- 单击、双击、右键菜单和 Enter 打开保持可用。
- 上下左右键可以稳定地在宫格中二维导航。
- 空结果、单结果、不完整末行等边界不会越界或崩溃。
- 新增导航单元测试通过，现有测试通过，项目构建通过。

## 非目标

- 不实现文件或图片拖放/粘贴解析；提示文案只是对齐参考图。
- 不新增“展开”按钮行为。
- 不改变搜索算法或最近使用排序逻辑。
- 不改造非主搜索页。
- 不改变窗口唤起、自动隐藏或前台应用恢复逻辑。
