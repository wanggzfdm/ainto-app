# 稳定筛选结果设计

## 目标

修复 Snippet 和 AI Commands 管理页在输入筛选词时的闪动和跳动，使筛选结果同步显示且窗口内容区尺寸稳定。

## 根因

两个页面根据筛选结果在两套不同高度的顶层内容之间切换：

- 有匹配项：列表与预览分栏，高度为 `360`。
- 无匹配项：独立空状态，高度为 `300`。

切换会改变父视图布局尺寸并重建滚动区域，导致输入时出现页面闪动和跳动。

## 设计

### 固定内容区

在 `SnippetView` 和 `AICommandView` 中，将筛选结果区域统一包裹在固定高度 `360` 的容器中：

- 有匹配项时，保留现有的列表与预览分栏。
- 无匹配项时，在相同容器中居中显示空状态。
- 不增加动画、延迟或 debounce；输入与筛选保持即时同步。

### 状态和焦点

- 保持现有 `TextField` 绑定和首项选中策略。
- 不变更筛选匹配规则。
- 不变更滚动、预览、编辑、删除或快捷键行为。
- 固定内容区高度，避免空状态和结果列表之间发生窗口尺寸变化。

## 测试

为页面的固定布局常量/状态决策提供单元测试，覆盖：

1. Snippet 页面有匹配项与无匹配项使用同一个内容区高度。
2. AI Commands 页面有匹配项与无匹配项使用同一个内容区高度。
3. 筛选词更新后，现有 ViewModel 的过滤结果仍能正确切换为空与恢复为匹配项。

测试通过 `swift test` 验证。

## 非目标

- 不调整视觉风格或文案。
- 不加入结果动画。
- 不重构 `SearchViewModel` 的筛选算法。
- 不修改其他输入框或 JSON 过滤功能。
